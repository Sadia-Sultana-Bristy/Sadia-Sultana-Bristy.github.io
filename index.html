About

I’m Sadia Sultana Bristy, a Software QA Engineer with nearly three years of experience testing insurance and SaaS web applications. I enjoy turning complex business requirements into reliable, high-quality software through a combination of thoughtful manual testing and practical automation.

I’m the tester who reads the rating rules before opening the application.

Insurance software is unforgiving. A missed state rule or a rounding error in a premium can become a compliance issue or an incorrect bill. I learned to test this domain by following the business logic, the data, and the money. From quote to bind, endorsements, renewals, and claims, I validate every workflow, then verify through APIs and SQL that the right data reaches the right place.

My foundation is strong manual testing. I design test cases from business requirements—not just from screens—and perform functional, regression, smoke, integration, end-to-end, and UAT testing. I work closely with business analysts, developers, and client stakeholders to clarify requirements, identify risks early, and write clear, reproducible bug reports that accelerate issue resolution.

Where automation delivers real value, I build it. Using Playwright (JavaScript) with the Page Object Model, I developed and maintained a regression suite that runs through GitHub Actions CI, allowing repetitive validation to be automated so testing efforts can focus on complex business scenarios and exploratory testing. I also perform API testing with Postman and Swagger, validate backend data using SQL, and use JMeter for basic performance testing to identify potential bottlenecks before release.

I’m passionate about continuous learning and improving software quality through collaboration, automation, and a deep understanding of business workflows. Whether I’m investigating a complex defect, improving a test framework, or validating a new feature, my goal is always the same: deliver software that users and clients can trust.

How I test a release

The same five steps, whether it’s a single feature or a full policy lifecycle.

  1. Read the requirements

    Business rules, rating tables and acceptance criteria come first. I clarify scope with stakeholders before writing a single case.

  2. Design the scenarios

    I build test matrices that cover the happy path, state-by-state variations, boundary values and the edge cases people forget.

  3. Test every layer

    I check the UI, the API in Postman or Swagger, the database with SQL and response times in JMeter, so a bug can’t hide behind a correct-looking screen.

  4. Report so it gets fixed

    Jira tickets include exact steps, expected and actual results, and evidence. I stay with each defect until the fix is verified.

  5. Protect what already works

    Regression and smoke passes run before sign-off. The repetitive parts run in Playwright on every build through GitHub Actions.
